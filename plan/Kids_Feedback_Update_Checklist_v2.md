# Kids_Feedback 업데이트 계획 · v2

> **목적:** AX/DX Engineer · AI Solution Engineer · Automation Engineer 채용 포트폴리오에 맞춰, 실제로 동작하는 **교육 피드백 자동화 워크플로**의 정확성·안정성·검증 근거를 완성한다.  
> **기준 저장소:** [wooya27/Kids_Feedback](https://github.com/wooya27/Kids_Feedback) (`main` 코드, 2026-11-11 확인)  
> **변경 핵심:** 기존 계획의 **'RAG 문서 5개 전체 임베딩'**을 **'지도 문서 20~30개로 확장 → 전체 인덱싱 → Top-k 검색 → 검색·생성 품질 평가'**로 상향했다.  
> **주의:** 아래 수치는 *개발 목표*다. 구현·실험 전에는 검색 정확도, 승인률, 시간 절감 등 성과로 표기하지 않는다.

## 0. 현재 구현 상태와 목표

| 영역 | 현재 확인 상태 | 이번 업데이트 목표 |
|---|---|---|
| FastAPI / PostgreSQL | 학생·수업·피드백 API 및 3개 데이터 모델 구현 | 실패 응답·DB 무결성·테스트 보강 |
| LangGraph | `retrieve → generate → review` / 최대 2회 생성 | **검증 최종 실패 시 DB 저장 금지** |
| RAG 문서 | `rag_docs/` 지도 문서 **5개** | **20~30개**의 검토된 지도 문서로 확장 |
| RAG 인덱스 | 위축형 칭찬법 문서 **1개에서 만든 벡터 8개** | 모든 문서 인덱싱, **60~120개 청크(초기 설계 목표)** |
| RAG 검색 | 코사인 유사도 **Top-1** | **Top-3 중심** 검색, 근거 출처, 낮은 관련도 처리 |
| Gemini | `gemini-2.5-flash` JSON 생성 | 형식·내용·근거 적합성 검증 |
| Human Review | `pending / approved / edited / rejected`와 메모·시각 저장 | **수정한 피드백 본문 저장**, 승인 전 전달 차단 |
| n8n | Webhook에서 `lesson_record_id: 1` 고정 | Webhook 입력 ID를 실제 API로 전달 |
| 평가 | `seed_eval.py`, `evaluate.py` 존재 | **40~50개 RAG 정답 질의 + API 35회 실행** |
| 문서·데모 | README는 제목뿐, Render 설정 파일 존재 | README·테스트 자료·실제 데모 증거 |

**가장 중요한 구분**

- **문서 5개 → 30개 자체는 성과가 아니다.** 더 다양한 학생·상황을 다루기 위한 *지식 범위 확장*이다.
- **청크 60~120개도 강제 목표가 아니다.** 문서가 다루는 질문 단위가 독립적으로 검색되도록 나눈 결과가 우선이다.
- **유사도 0.70 이상은 정답률이 아니다.** 실제 올바른 문서가 검색됐는지, 사람이 만든 정답셋으로 측정해야 한다.

## 2. P0 · RAG를 핵심 경쟁력으로 강화 (이번 계획의 가장 큰 변경)

### - [x] P0-3. 지도 문서 5개 → 20~30개로 확장  ✅(2026-11-12, MVP 15개/102청크 · 정식 22~30개는 추후 확장)

**왜 필요한가?** 현재 지도 문서의 수와 성향·수업 상황의 범위가 좁다. 성향이 다른 학생에게도 거의 같은 근거가 전달될 위험이 있다. 지도 기준을 넓히되, 중복 문서를 양산하지 않고 **상황별로 실질적으로 다른 조언이 검색되도록** 설계한다.

#### 추천 문서 분류 · 작성 목표

| 분류 | 목표 | 주제 예시 |
|---|---:|---|
| 학생 성향별 지도 | **8~10개** | 위축·낯가림, 완벽주의, 승부욕, 주의 집중 어려움, 자신감 있는 리더, 소극적 참여, 활발한 참여, 차분한 성향 등 |
| 수업 상황별 대응 | **7~10개** | 반복 실패, 작은 성공, 수업 참여 거부, 또래 갈등, 집중 이탈, 규칙 이해 어려움, 새로운 동작 도전, 순서 기다리기 등 |
| 학습 성장·목표 | **3~5개** | 줄넘기 수준별 목표, 전회차 대비 성장 관찰, 다음 단계 난이도, 동기 유지 등 |
| 학부모 소통 | **4~5개** | 성취 전달, 어려움 설명, 가정 연계 활동, 과장·진단 표현 회피, 민감정보 전달 원칙 등 |
| **합계** | **22~30개** | 기존 문서 5개를 점검·개정하여 포함하고, 부족한 주제를 추가 |

**작성 품질 기준**

- [ ] 각 문서는 **제목 / 어떤 상황에 쓰는지 / 권장 언어·행동 / 피해야 할 표현 / 예시 / 출처·검토 여부**를 기록한다.
- [ ] 한 청크는 가능한 한 **하나의 질문에 답할 수 있는 독립적인 지침**으로 작성한다.
- [ ] RAG 인덱스의 **문서 ID·섹션 ID·출처·버전**이 원문과 연결되도록 한다.
- [ ] 근거 없는 교육 효과·진단처럼 보이는 표현·아동 낙인을 주는 서술은 넣지 않는다. 학생 특성은 가능한 한 관찰 가능한 행동으로 기술한다.
- [ ] 문서의 출처가 확인되지 않으면 **자체 작성 가이드(전문가 검증 전)**로 표시하고, 공식 지도 규정처럼 소개하지 않는다.
- [ ] 아동 실명과 실제 민감정보는 문서·샘플에 넣지 않는다.

**완료 기준:** 20개 이상, 권장 22~30개 문서가 명확한 주제로 정리되고, 인덱싱 전 출처·내용 점검을 마친다. 30개를 채우기 위한 중복 문서는 만들지 않는다.

## 5. 실행 순서 · 현실적인 작업 일정

**권장 순서:** 위험한 저장 흐름 수정 → 지도 문서 확장 → 인덱싱 → 검색·품질 평가 → n8n/검수/문서 마감.  
다만 **n8n 동적 ID 수정은 작업량이 작아** P0 첫날 함께 끝내도 된다.

| 단계 | 작업 | 예상 소요(개발환경 준비 기준) | 제출 증거 |
|---|---|---:|---|
| 1 | 실패 시 저장 차단 + 단위 테스트 | **2~4시간** | 실패 응답과 DB 미저장 |
| 2 | n8n 동적 ID 전달 | **1~2시간** | 서로 다른 수업 ID 처리 |
| 3 | 지도 문서 **20~30개 작성·정리·검토** | **8~16시간 이상** | 문서 분류·출처 목록 |
| 4 | 전체 인덱싱 + Top-3 검색 | **4~7시간** | 20~30문서, 청크·출처 로그 |
| 5 | RAG 질문 **40~50개** 정답셋 + Hit@k 평가 | **4~7시간** | 검색 지표·실패 사례 |
| 6 | RAG 적용 전/후 피드백 비교 | **2~4시간** | 학생별 출력·근거 비교 |
| 7 | API 35회 평가 실행 + Human Review 보강 | **4~8시간 이상** | 실제 지표·검수 API 결과 |
| 8 | README·테스트·포트폴리오 3페이지 갱신 | **3~5시간** | 최종 제출 자료 |

**전체 참고:** 약 **28~53시간 이상**. 문서 검토 수준, API 호출 제한, 기존 코드 오류에 따라 늘 수 있다. 특히 문서의 출처 확인과 신뢰성 검토는 속도보다 품질을 우선한다.

### 시간 부족 시 제출용 최소 완성(MVP)

- [ ] **우선**: 검증 실패 저장 차단·n8n 동적 ID·관련 회귀 테스트.
- [ ] **RAG 1차**: 가장 우선순위 높은 성향/상황 **10~12개 문서**부터 검토·전체 인덱싱·Top-3 적용.
- [ ] **정식 목표**: 20~30개 문서로 확장한 뒤 40~50개 질의로 정량 평가.
- [ ] 숫자를 측정하지 못했으면 '향후 검증 예정'으로 표시하고 기존 프로젝트에서 검증된 사실만 제출.
