# API 평가 결과 (P1-2) — 35회 실행

> `seed_eval.py`(테스트DB에 합성 8명/21기록 시딩) → `evaluate.py`(유효 30 + 에러 5 = 35회) 실행 결과.
> 원시 데이터: `metrics.json`. 2026-11-12 실측(도커 컨테이너 내부 실행).

## 실행 구성
- 유효 케이스 **30건** = 기록 21건 + 앞 9건 반복(일관성 확인).
- 에러 케이스 **5건** = 존재하지 않는 수업 ID(999999, 0, -1, 888888, 123456).
- LLM `gemini-2.5-flash` · RAG 102청크 인덱스(Top-3).

## 지표 (실측)
| 지표 | 값 | 의미 |
|---|---|---|
| API E2E 성공률 | **100.0%** | 30건 모두 200 + 필수필드 완비 |
| JSON 형식 성공률 | **100.0%** | 세 필드 모두 유효 |
| 유사도 임계값(0.70) 통과율 | **100.0%** | ⚠️ **정답률 아님** (유사도 바닥선 통과율). 정답률은 Hit@k(`rag_evaluation.md`) 참고 |
| 유사도 min/avg/max | 0.7882 / 0.8246 / 0.8752 | 검색 근거 유사도 분포 |
| 평균 응답시간 | **14.55s** | Top-3 컨텍스트 + 생성 포함 |
| 중앙값 / p95 | 14.8s / **18.62s** | 응답 지연 분포 |
| 에러 처리율 | **100.0%** | 잘못된 ID 5건 모두 404로 안전 처리 |
| 시뮬레이션 검수 승인/수정/거절 | 100% / 0% / 0% | ⚠️ **규칙 기반 시뮬레이션** (실제 강사 검수 아님) |

## 반드시 함께 쓸 주의
- **"유사도 임계값 통과율"은 검색 정답률이 아니다.** 실제 정답률(Hit@1/@3)은 사람이 만든 정답셋으로 `evals/evaluate_retrieval.py`에서 별도 측정.
- **Human Review 수치는 `simulated_review()` 규칙 기반**이다(필드 완비+유사도 통과면 approved). 실제 강사 판단이 아니므로 "승인율 100%"를 실제 품질 승인으로 해석하면 안 된다.
- **응답시간 ~15s는 느린 편**이다. Top-3 컨텍스트로 토큰이 늘어난 영향 포함. 실사용 전 최적화 여지.
- 모든 데이터는 합성이며 전용 테스트 DB에서 실행했다(`seed_eval.py`는 TRUNCATE).

## 재현
```bash
docker compose exec -T api python seed_eval.py     # ⚠️ 테스트DB 전용(TRUNCATE)
docker compose exec -T api python evaluate.py        # metrics.json 생성(컨테이너 내부)
docker compose cp api:/app/metrics.json ./metrics.json
```
