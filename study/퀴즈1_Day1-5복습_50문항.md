# ✅ [답지와 해설]

**1. ②** — 요청은 항상 main(교통정리)→router(처리)→database(연결)→models(DB)→schemas(모양)→응답 순.
**2. ②** — main.py는 안내데스크. 앱을 켜고 요청을 라우터로 연결.
**3. ③** — router는 주방 코너. 실제 넣기/꺼내기 로직 처리.
**4. ③** — models.py = 창고 선반 설계도(DB 테이블의 진짜 모양).
**5. ②** — schemas.py = 주문서/영수증 양식. 데이터 검사.
**6. ②** — database.py는 문지기. get_db로 연결 열고 닫음.
**7. ②** — 역할별로 나눠야 관리가 쉬워서. 한 파일에 다 넣으면 괴물이 됨.
**8. ②** — models→schemas→router→main. 새 기능마다 반복되는 뼈대.
**9. ③** — Day 2 대상은 아이(Child).
**10. ②** — Day 3 대상은 수업기록(LessonRecord).
**11. ③** — Day 5 대상은 피드백(Feedback).
**12. ②** — POST=새 데이터 생성, PATCH=기존 데이터 일부 수정.
**13. ②** — exclude_unset=True는 사용자가 실제 보낸 필드만. None 덮어쓰기 방지.
**14. ②** — setattr(객체,"속성",값) = 객체.속성 = 값.
**15. ①** — 한쪽만 있으면 서버 켤 때 에러. 양쪽에 다 써야 함.
**16. ③** — 전체는 `.all()`, 하나는 `.first()`.
**17. ②** — 왼쪽=DB 컬럼(저장된 것), 오른쪽=URL로 들어온 값.
**18. ②** — id는 그 표에서 자기 자신의 고유 번호(기본키).
**19. ①** — child_id는 children의 id를 베껴 적은 연결고리(외래키).
**20. ②** — add(담기)→commit(저장확정)→refresh(최신상태 다시 읽기).
**21. ②** — server_default=func.now()로 DB가 자동 입력해서 안 보냄.
**22. ②** — Pydantic v2에서 orm_mode → from_attributes.
**23. ②** — 연습 데이터라 drop_all로 싹 지우고 create_all로 재생성. (실무는 Alembic)
**24. ②** — prompt_service는 글 조립만. AI는 아직 안 부름(주문서 작성).
**25. ②** — llm_service는 조립된 글을 Gemini에 보내고 답 받기(주방에 주문).
**26. ①** — f-string: 문자열 앞 f + {변수} 자리에 값이 들어감.
**27. ②** — 함수 밖에 두면 프로그램 켤 때 1번만. 매번 다시 하는 낭비 방지.
**28. ③** — .env에 숨기고 .gitignore로 제외. 코드/깃허브에 노출 금지.
**29. ②** — json.loads: 문자열 → 파이썬 딕셔너리. 그래야 data["key"]로 꺼냄.
**30. ②** — 없는 ID로 500 크래시 전에 404 "없음"을 깔끔히 알림.
**31. ②** — 리스트 응답은 List[...]로 감쌈. `from typing import List` 필요.
**32. ②** — from_attributes로 DB 객체를 Pydantic이 읽어 JSON 변환 허락.
**33. ②** — 매개변수 = 부를 때 채워질 빈 그릇. 호출하는 쪽이 값을 넣음.
**34. ②** — 위쪽 "Server response"의 Code가 진짜 결과. 아래 표는 문서용.
**35. ②** — import + include_router 2줄로 연결해야 작동.
**36. ②** — main→router→database→models→schemas→응답.
