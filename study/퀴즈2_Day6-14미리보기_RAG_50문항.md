# ✅ [답지와 해설]

**1. ②** — 통합 테스트는 부품을 조립해 처음~끝까지 실제로 굴러가는지 확인. 숨은 버그가 여기서 나옴.
**2. ②** — 코드 새로 안 짬. 이미 만든 API를 Swagger에서 순서대로 클릭.
**3. ②** — README = API 명세 + ERD + 회고.
**4. ②** — ERD는 테이블(children─lesson_records─feedbacks) 관계 그림.
**5. ②** — 마무리(6~7) / RAG(8~11) / Streamlit(12~14) 3덩어리.
**6. ②** — Retrieval + Augmented + Generation.
**7. ②** — 답 시키기 전에 관련 참고자료를 찾아 프롬프트에 끼워주는 것.
**8. ②** — 지금 AI = 아무것도 안 보고 시험 보는 학생.
**9. ①** — RAG = 관련 페이지 펴서 보고 답하는 오픈북 학생.
**10. ②** — 양이 많아 다 못 넣고, 상관없는 내용이 섞여 답이 산만해짐.
**11. ②** — 청크 = 긴 문서를 자른 작은 조각.
**12. ①** — Chunking = 문서를 조각으로 쪼개는 작업.
**13. ①** — 임베딩 = 문장을 지도 위 점(숫자)으로 바꾸기.
**14. ②** — 벡터 = 그 점의 좌표값(숫자 목록, 예 [0.1,-0.8,...]).
**15. ②** — 벡터 DB = 점들을 저장하고 가까운 것을 찾아주는 창고.
**16. ①** — Retrieval = 질문과 가까운 조각 찾아오기.
**17. ②** — 검색 결과는 rag_context 자리에 들어감.
**18. ②** — 뜻이 비슷하면 지도에서 가까이 찍힘.
**19. ②** — 두 점의 거리가 가까운지 재서 판단.
**20. ①** — 질문도 점으로 찍고 제일 가까운 자료 점을 집음.
**21. ②** — 준비 단계는 프로그램 켤 때 미리 1번(문서→쪼개기→임베딩→저장).
**22. ②** — 실행 단계는 피드백 만들 때마다 돎(질문 임베딩→검색→끼움→생성).
