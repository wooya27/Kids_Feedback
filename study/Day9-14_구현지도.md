# Day 9~14 구현 지도 (비전공자용)

> 목적: 구현하다가 "아, 이게 그때 그 개념이다!"가 되도록 미리 지도를 그려둔다.
> 이 문서는 **개념 + 왜 + 어떻게 + 과정**을 담은 참고서다. (실제 코드는 세션 때 네 손으로 씀)

> 표기: 🖐️ = 네가 직접 칠 학습 대상 / 🧱 = 그냥 깔아주는 보일러플레이트

## 📖 이 문서 읽는 법 (중요 — 처음 읽을 때)

이 문서는 **두 가지 용도**로 쓰인다. 읽는 시점에 따라 보는 곳이 달라:

**① 구현 전 "미리 이해"용 (지금 너)**
→ **글로 된 부분만 읽어.** 각 Day의 `뭘 하나 / 개념 / 왜 하나 / 과정`, 그리고 🔑 표시.
→ **회색 코드박스는 지금 다 이해하려 하지 마.** 넘겨도 돼. "이런 게 나오는구나" 정도만.
→ 코드박스 안의 어려운 문법(반복문, numpy 등)은 그때그때 세션에서 손으로 치며 배운다.

**② 구현 중 "옆에 두고 참고"용 (나중)**
→ 그때 코드박스를 보며 골격을 따라 친다.

즉 **지금은 "무엇을·왜"만 이해하면 충분.** "어떻게(코드)"는 몰라도 정상이야.
코드가 안 읽혀도 겁먹지 마 — 원래 이 순서(개념 먼저, 코드 나중)로 배우는 거야.

# Day 9 — 임베딩 + 저장 + 검색 🔴 (제일 큰 고비)

> 이미 한 것: chunking (`##`로 조각내기). 이제 그 조각들을 "검색 가능"하게 만든다.

## 9-1. 이 단계에서 뭘 하나
1. 조각들을 **숫자(벡터)로 바꾼다** = 임베딩(embedding)
2. 그 숫자들을 **저장**해둔다
3. 질문이 오면 질문도 숫자로 바꿔서 **가장 닮은 조각을 찾아온다** = 검색(search)

## 9-2. 개념 ①: 임베딩 = "글을 숫자 목록으로 바꾸는 것"

컴퓨터는 "위축형", "칭찬" 같은 **글자의 뜻**을 모른다. 대신 글을 **숫자 목록**으로 바꿔놓으면,
숫자끼리 얼마나 가까운지로 "뜻이 비슷한지"를 계산할 수 있다.

```
"위축형 아이 칭찬법"   →  [0.12, -0.44, 0.98, ... ]   ← 숫자 수백 개짜리 목록 (이게 벡터)
"자신감 없는 애 칭찬"  →  [0.11, -0.41, 0.95, ... ]   ← 뜻이 비슷하면 숫자도 비슷하게 나옴
"줄넘기 준비물"        →  [-0.88, 0.02, 0.31, ... ]   ← 뜻이 다르면 숫자도 딴판
```

- **벡터(vector)** = 그냥 "숫자 목록"이라는 뜻. 무서운 말 아님.
- **왜 하나:** 컴퓨터가 "뜻이 비슷한 걸 찾게" 하려고. 글자로는 못 비교하니까 숫자로 바꾸는 것.
- 이 변환을 해주는 게 **임베딩 모델** (우리는 Gemini의 임베딩 기능을 부른다).

> 🔑 "아 이게 그 개념": chunk에서 배운 **②독립 테스트**가 여기서 빛을 봐.
> 조각이 혼자서 뜻이 완결돼야, 숫자로 바꿨을 때도 뜻이 또렷하게 찍혀서 검색이 잘 된다.

## 9-3. 개념 ②: 유사도 = "두 숫자 목록이 얼마나 닮았나"

숫자로 바꿔놨으면, 두 벡터가 **얼마나 닮았는지** 점수를 낸다. 이 점수를 **유사도(similarity)**라 한다.
가장 많이 쓰는 방식이 **코사인 유사도** — "두 화살표가 같은 방향을 보나"를 재는 것 (1에 가까울수록 닮음).

- 이유까지 다 알 필요 없음. **"닮을수록 점수 높다"**만 알면 시작 가능.
- 검색 = 질문 벡터와 **모든 조각 벡터의 유사도를 재서, 점수 높은 순 몇 개를 꺼내는 것.**

## 9-4. 과정 (5단계)
```
① chunking      : 파일 → 조각 리스트         ← 이미 함 (kids.py)
② embed(조각들)  : 각 조각 → 벡터            ← Gemini embed 호출
③ 저장          : (조각글 + 벡터) 짝지어 보관  ← 리스트나 파일에
④ embed(질문)    : 질문도 벡터로              ← 같은 함수 재사용
⑤ search        : 질문벡터 ↔ 조각벡터들 유사도 → 상위 몇 개 조각 반환
```

## 9-5. 핵심 코드 골격 (패턴만 — 실제는 네가 채움)

**깔 것 (🧱):** 계산용 라이브러리 `numpy` (유사도 계산에 씀)
```
pip install numpy
```
(임베딩은 이미 있는 google-genai로 하니까 추가 설치 X)

**② 임베딩 함수** 🖐️ — 조각 하나를 벡터로 바꾸는 것. 우리 `generate_feedback`이 Gemini를 부른 것처럼, 이번엔 임베딩을 부른다:
```python
# 개념 골격 (정확한 모델명·필드는 공식문서에서 확인해 채우기)
from google import genai
client = genai.Client(api_key=api_key)

def embed(text):
    result = client.models.embed_content(
        model="gemini-embedding-001",   # ← 임베딩 전용 모델 (생성 모델 gemini-2.5-flash와 다름!)
        contents=text,
    )
    return result.embeddings[0].values   # 숫자 목록(벡터)만 꺼내서 돌려줌
```
> 🔑 "아 이게 그 개념": `generate_feedback`이 "글 써줘"라고 Gemini 부른 거랑 똑같은 패턴.
> 이번엔 "이 글을 숫자로 바꿔줘"라고 부르는 것뿐. **client 부르기 → 결과에서 필요한 값 꺼내 return.**

**③ 저장** 🖐️ — 조각글과 벡터를 짝지어 보관:
```python
chunks = text.split("##")                 # 조각 리스트 (Day 8~9)
db = []                                     # 우리만의 작은 창고
for c in chunks:
    db.append({"text": c, "vector": embed(c)})   # {조각글, 벡터} 한 세트씩 쌓기
```

**⑤ 검색** 🖐️ — 질문과 가장 닮은 조각 찾기 (numpy로 유사도):
```python
import numpy as np

# 두 벡터가 얼마나 닮았는지 점수를 내주는 계산기 (1에 가까울수록 닮음)
def cosine(a, b):
    a, b = np.array(a), np.array(b)
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

def search(question, top_k=3):
    q = embed(question)                 # 1) 질문을 벡터로 바꾼다
    scored = []                         # 2) (점수, 조각글) 담을 빈 리스트
    for item in db:                     # 3) 저장된 조각을 하나씩 꺼내며
        score = cosine(q, item["vector"])       # 질문과 얼마나 닮았나 점수 계산
        scored.append((score, item["text"]))    # (점수, 조각글) 짝을 리스트에 추가
    scored.sort(reverse=True)           # 4) 점수 높은 순으로 정렬
    top = scored[:top_k]                # 5) 위에서 top_k개(기본 3개)만 자른다
    result = []                         # 6) 조각글만 골라 담을 리스트
    for score, text in top:
        result.append(text)             # 점수는 버리고 조각글만 담기
    return result                       # 닮은 조각 3개를 돌려줌
```

**말로 풀면:** ①질문을 숫자로 바꾸고 → ②③저장된 조각마다 "질문과 얼마나 닮았나" 점수를 매겨서 → ④점수순 줄 세우고 → ⑤위 3개만 → ⑥조각 글만 돌려준다.
- `np.dot`, `np.linalg.norm` = numpy가 주는 계산기 함수. **지금은 "닮은 정도를 숫자로 내주는 공식"으로만 이해하면 됨.** 안을 외울 필요 X.
- `db` = ③단계에서 만든 우리 창고 (조각글+벡터 세트들).

> 🔑 "아 이게 그 개념": `top_k=3` = "제일 닮은 3개만" (예전 `GET`에서 "최근 5개만" 자른 거랑 같은 발상).

## 9-6. Day 9 완료 기준
- `search("위축형 아이 칭찬")` 넣으면 → 위축형 칭찬 조각이 상위에 나오면 성공.

# Day 10 — RAG를 피드백에 연결

## 10-1. 이 단계에서 뭘 하나
Day 9에서 만든 `search()`가 찾아온 조각을, **`build_prompt()`의 프롬프트 안에 끼워넣는다.**
그럼 Gemini가 "우리 학원 노하우"를 참고해서 피드백을 쓴다.

## 10-2. 왜 하나
지금 `build_prompt`는 아이 정보 + 수업기록만 넣는다. 여기에 **관련 노하우 조각**을 더 넣으면,
Gemini가 일반론이 아니라 "이 학원 방식"으로 답한다. (RAG의 최종 목적)

## 10-3. 어떻게 — 과정
```
① 이 아이 성향으로 질문 만들기   예) "위축형 아이 칭찬법"
② search(질문) → 관련 조각 3개
③ 그 조각들을 하나의 글로 합치기
④ build_prompt에 [참고 노하우] 자리 새로 만들어 끼우기
```

## 10-4. 핵심 코드 골격 🖐️
`prompt_service.py`의 `build_prompt`를 살짝 고친다:
```python
def build_prompt(child, records, rag_context):    # ← 매개변수 하나 추가
    ...
    prompt = f"""[역할]
...
[최근 수업 기록]
{records_text}

[참고할 우리 학원 노하우]         ← 새 구역 추가
{rag_context}                    ← 검색해온 조각들이 여기 들어감

[작성 규칙]
...
"""
    return prompt
```
그리고 이 함수를 부르는 곳(`feedbacks_router.py`)에서 검색을 먼저 해서 넘긴다:
```python
question = f"{child.personality} 아이 피드백"     # 아이 성향으로 질문 생성
context = "\n".join(search(question))            # 조각 3개를 한 덩어리 글로
prompt = build_prompt(child, records, context)   # 끼워서 주문서 완성
```
- `"\n".join(리스트)` = 리스트에 든 조각 3개를 **줄바꿈으로 이어 하나의 글**로 만드는 것. (`split`의 반대라고 보면 됨 — split은 자르고, join은 붙임)
> 🔑 "아 이게 그 개념": `build_prompt`에 `records_text` 끼운 거랑 **똑같은 방식.**
> 자리(구역) 하나 더 만들고, 거기에 검색 결과를 f-string으로 끼우는 것뿐.

## 10-5. 완료 기준

# Day 12 — Streamlit 기본 (화면 만들기)

## 12-1. Streamlit이 뭐고 왜 쓰나
**Streamlit** = 파이썬 몇 줄로 웹 화면을 만들어주는 도구. HTML/CSS 몰라도 됨.
강사가 터미널·코드가 아니라 **버튼과 입력칸**으로 우리 프로그램을 쓰게 하려고 붙인다.

## 12-2. 시작 최소 개념
- `st.title("제목")` → 큰 글씨 제목
- `st.text_input("라벨")` → 입력칸 (강사가 글 씀)
- `st.button("생성")` → 버튼 (누르면 아래 코드 실행)
- `st.write(값)` → 화면에 결과 출력

## 12-3. 핵심 골격 🖐️
```python
import streamlit as st

st.title("아이 피드백 생성기")
child_id = st.text_input("아이 ID를 입력하세요")
if st.button("피드백 생성"):        # 버튼 누르면 이 안이 실행됨
    st.write("여기에 결과 표시 예정")
```
깔 것 🧱: `pip install streamlit` / 실행: `streamlit run 파일.py`

## 12-4. 공식문서 / 검색어
- **"Streamlit get started"** (docs.streamlit.io)
- 유튜브: "Streamlit 기초 한국어"

# Day 13 — 화면 ↔ 우리 API 연결

## 13-1. 뭘 하나
Day 12 버튼을 누르면 → **우리가 만든 FastAPI(피드백 생성 API)를 호출** → 결과를 화면에 표시.

## 13-2. 개념: 화면과 서버는 남남 → 요청으로 대화
Streamlit 화면과 FastAPI 서버는 **서로 다른 프로그램**이다. 화면이 서버에게
"이 아이 피드백 만들어줘"라고 **요청(request)**을 보내고, 서버가 결과를 **응답(response)**한다.
- 이 심부름꾼이 `requests` 라이브러리 (또는 httpx).

## 13-3. 핵심 골격 🖐️
```python
import requests

if st.button("피드백 생성"):
    res = requests.post(f"http://localhost:8000/feedbacks/generate",
                        json={"child_id": child_id})   # 우리 API 호출
    data = res.json()                                   # JSON 응답 받기
    st.write(data["parent_feedback"])                   # 화면에 표시
```
> 🔑 "아 이게 그 개념": 예전에 브라우저 `/docs`에서 손으로 눌러 API 부른 거를,
> 이제 **화면 버튼이 대신 눌러주는** 것. `json.loads`로 다뤘던 그 JSON이 여기 `res.json()`.

- **"streamlit call fastapi"**
