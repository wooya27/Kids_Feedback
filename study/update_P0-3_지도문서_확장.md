# [업데이트 단계 3] P0-3 · 지도 문서 5개 → 15개(MVP)로 확장

> 목표: 성향이 다른 학생·다양한 수업 상황에도 **실질적으로 다른 조언**이 검색되도록 지식 범위를 넓힌다.
> 이번엔 MVP로 15개(성향7·상황4·성장1·학부모3), 총 102개 청크 확보. (정식 목표 22~30개는 이후 확장)

---

## 1. "문서 수 늘리기"가 목표가 아니다 (중요한 구분)
- 5→15 자체는 성과가 아니라 **지식 범위 확장**이다.
- 중복 문서를 만들지 않고, **상황별로 다른 조언이 검색되게** 설계하는 것이 핵심.
- 그래서 기존 위축형 2개(칭찬/적극성)와 겹치는 '소극형'은 일부러 추가하지 않고, 아직 없던 성향(완벽주의/산만/리더)과 상황(반복실패/또래갈등/집중이탈/순서기다리기)을 채웠다.

## 2. 문서 1개의 구조 (청킹을 염두에 둔 설계)
```
# 제목 (성향/상황 + 무엇을 다루는지)
> meta: category=성향별; source=자체작성가이드(전문가검증전); version=2026-11-12   ← 기계가 읽는 메타
> 골격 안내 + ⚠️ 검증 전 자체 작성 고지
## 질문: ...?           ← 청크 1 (독립적인 질문 1개)
    (답: 상황 → 할 말 → 왜 효과적)
## 질문: ...?           ← 청크 2
    ...
```
- **왜 `## 질문` 단위로 쪼개나?** RAG는 "질문 1개 = 청크 1개"로 나눠야 검색이 정확하다. 한 청크에 여러 주제가 섞이면 엉뚱하게 뽑힌다. (P0-4에서 `##` 기준으로 청킹)

## 3. 메타 라인 규칙 (인덱스 연결용)
```
> meta: category=<성향별|상황별|성장목표|학부모소통>; source=자체작성가이드(전문가검증전); version=YYYY-MM-DD
```
- 제목(H1) **바로 다음 줄**에 둔다.
- P0-4의 `build_index.py`가 이 줄을 파싱해 각 청크에 `category`, `source`, `version`을 붙인다.
- 기존 5개 문서에도 이 줄만 **추가**(내용은 보존)했다.

## 4. 품질·안전 기준 (아동 대상이라 보수적으로)
- 진단성 표현 금지: "ADHD/발달지연" → "집중 유지 시간이 짧은 모습이 보여요"(관찰).
- 낙인 금지: 성향 라벨을 학부모에게 그대로 노출하지 않음(민감정보 문서에 원칙 명시).
- 근거 미확인 → `source=자체작성가이드(전문가검증전)`로 반드시 표기, 공식 규정처럼 소개하지 않음.
- 실명·실제 민감정보 배제, 데모는 합성 데이터만.

## 5. 현재 분류·청크 집계
| 분류 | 문서 | 청크 |
|---|---:|---:|
| 성향별 | 7 | 52 |
| 상황별 | 4 | 24 |
| 성장목표 | 1 | 7 |
| 학부모소통 | 3 | 19 |
| 합계 | 15 | 102 |
→ 상세 목록: `docs/rag_documents_index.md`

## 6. 알아야 하는 명령어
```bash
# 문서 수
ls rag_docs/*.md | wc -l
# 파일별 청크(## 질문) 수
for f in rag_docs/*.md; do echo "$(grep -c '^## ' "$f")  $f"; done
# 전체 청크 합계
grep -rc '^## ' rag_docs/*.md | awk -F: '{s+=$2} END{print s}'
```

## 7. 구현 흐름 (내가 한 순서)
1. 기존 5개 문서 읽고 중복 주제 파악 → 겹치지 않는 범주 선정.
2. 기존 5개에 메타 라인만 추가(내용 보존).
3. 신규 10개 작성(성향3·상황4·성장1·학부모2), 전부 '검증 전 자체작성'으로 표기.
4. 문서·청크 집계 → `docs/rag_documents_index.md` 작성.

## 8. 한 줄 요약
> 중복 없이 '서로 다른 조언'이 뽑히도록 성향·상황·성장·학부모 범주를 15개 문서/102청크로 넓혔고,
> 각 문서는 `## 질문` 단위로 쪼개고 상단 메타 라인으로 분류·출처를 기계가 읽게 했다.
