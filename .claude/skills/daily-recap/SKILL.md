# 하루 작업 정리 + 학습 문서 + 암기 시트 (daily-recap)

작업하면서 사용한 기술스택·툴·명령어를 정리하고, 그날 배운 것을
`study/` 폴더에 학습 문서로 남기고, 내가 외워야 할 것을 암기 시트로 뽑아준다.
목적은 "오늘 한 게 그냥 흘러가지 않고 내 실력으로 남게" 만드는 것이다.
기간을 따로 말하면 그 기간을, 안 말하면 오늘을 대상으로 한다.

## 먼저 할 일 (근거 수집)
출력 전에 아래를 확인해 "실제로 한 것"만 정리한다. 추측으로 채우지 않는다.
1. 이번 세션 대화에서 실제로 다룬 작업/개념.
2. `git log --since="..." --oneline`, `git diff --stat` 으로 바뀐 파일·커밋.
3. 새로 설치/실행한 패키지·CLI 명령 (package.json, requirements 등 변경 포함).
4. `study/` 폴더의 기존 day 문서를 훑어 "이미 배운 것(🔁)"과 "오늘 처음 한 것(🆕)"을 구분.

## 출력 형식 (정확히 이 순서)

### 🧰 오늘 쓴 기술스택 / 툴
- `이름` — 이게 뭔지 + 오늘 어디에/왜 썼는지 (비전공자 눈높이 한 줄, 🆕/🔁 표시)

### ⌨️ 오늘 친 명령어 / 커맨드
실제로 실행한 것 중 외울 가치 있는 것만 표로.
| 명령어 | 하는 일 | 언제 쓰나 |
|---|---|---|

### 🧠 암기 시트 (내일 안 보고 쳐볼 것)
플래시카드 형식, 핵심만 5개 이내.
1. **앞면:** (질문/"OOO 하는 명령어는?") → **뒷면:** (답 + 한 줄 이유)

## 📚 study/ 학습 문서 만들기 (Day 작업이 끝났을 때)
한 Day의 작업이 완료됐으면, `study/` 폴더에 `day2.md`, `day3.md` 형식으로
학습 문서를 만들거나(이미 있으면) 이어서 채운다.
- **포함할 내용:** 그날 배운 핵심 개념 / 내가 물어봤던 질문과 답변 / 주요 코드 패턴과 설명.
- **목적:** 내가 나중에 혼자 복습할 수 있게. 그래서 "읽어서 아는 척"이 아니라
  "안 보고 다시 떠올릴 수 있게" 개념→이유→예시 순으로 쓴다.
- 새 기술/개념을 내가 직접 적용하는 데 성공한 것은 해당 day 문서에 반드시 남긴다
  (다음에 같은 게 나오면 이 문서를 기준으로 "저번에 했던 거"라고 판단한다).

## 톤
- 비전공자 기준 쉬운 말. 전문용어는 처음 나올 때 한 번 풀어준다.
- 평가/칭찬보다 "이건 외워두면 두고두고 편하다" 식으로 우선순위만 짚어준다.
